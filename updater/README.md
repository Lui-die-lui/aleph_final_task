# 기록 갱신 장치 (BR-A)

리추얼 기록·출석 기록·제출 현황을 넣으면 사이트의 **숫자 칸**과 **세 능력(자기조절력·대인관계력·자기동기력)별 문단 후보**를 다시 만듭니다.
후보는 자동으로 공개되지 않습니다. 본인이 `approvals/approved.json`에 승인한 문장만 공개 데이터(`output/site-records.json`)에 들어갑니다.

- 필요한 것: Python 3.10 이상 (표준 라이브러리만 사용, 설치할 패키지 없음, 네트워크·AI 호출 없음)
- 같은 입력 + 같은 승인 파일 → 같은 바이트의 결과 (현재 시각·무작위 값을 쓰지 않음)

## 실행 방법 (세 단계)

1. **입력 넣기** — `inputs/` 폴더에 `ritual.json`(리추얼 기록 원본), `attendance.csv`(출석 기록), `submissions.csv`(제출 현황)를 넣습니다. 아직 없는 파일은 넣지 않아도 됩니다(그 숫자는 "자료 확인 후 반영"으로 나옵니다). CSV 형식은 `examples/`를 따릅니다.
2. **실행** — 이 폴더에서 `python update_records.py --publish-to ../site/data/records.json`을 실행합니다. `output/`에 숫자·후보·공개 데이터가 생기고, 공개 데이터가 사이트 폴더로 복사됩니다. (사이트 폴더가 없으면 `--publish-to` 없이 `python update_records.py`만 실행합니다.)
3. **승인 후 다시 실행** — `output/candidates.md`에서 쓸 후보의 id를 `approvals/approved.json`에 옮기고, 직접 다듬은 문장을 `text`에 적은 뒤 `"approved": true`로 바꿉니다. 2단계를 다시 실행하면 승인한 문장만 반영됩니다. 사이트는 `site` 폴더에서 `npm run build`로 다시 만듭니다.

재현성 확인: `python verify_twice.py` → 새 임시 폴더에서 두 번(+다른 새 폴더에서 한 번) 실행해 SHA-256을 비교하고 `verification/reproducibility.md`에 기록합니다.

## 입력

| 파일 | 형식 | 없거나 비었을 때 |
|---|---|---|
| `inputs/ritual.json` | `{"student": ..., "days": [{"date": "YYYY-MM-DD", "open": ["항목: 내용", ...], "close": [...]}]}` | 리추얼 숫자 "자료 확인 후 반영", 후보 없음 |
| `inputs/attendance.csv` | `date,status,note` / status: 출석·지각·조퇴·결석·공결 | 출석 "자료 확인 후 반영" |
| `inputs/submissions.csv` | `task_id,title,due_date,submitted_date,status` / status: 제출·미제출·지연제출 | 제출 "자료 확인 후 반영" |

`inputs/`의 원본은 사적인 내용이 있을 수 있으므로 사이트·ZIP에 넣지 않습니다.

## 출력

| 파일 | 내용 | 공개 여부 |
|---|---|---|
| `output/metrics.json` | 숫자마다 정의·기간·출처(파일, 반영 상태) | 공개 가능 |
| `output/candidates.json`, `output/candidates.md` | 세 능력별 문단 후보(날짜, 항목명, 원문 근거) | **공개 금지 · 본인 검토용** |
| `output/site-records.json` | 숫자 + 기록 날짜 목록(잔디 달력) + 승인된 문단 | 공개 데이터 |

## 숫자 계산 방식

- **리추얼 기록일**: 시작(open) 또는 마무리(close) 기록이 한 줄 이상 있는 날짜 수
- **기록이 있는 주**: 첫 기록 주의 월요일부터 마지막 기록 주까지의 달력 주 중 기록이 1일 이상 있는 주
- **시작·마무리를 모두 쓴 날**: 같은 날짜에 open·close가 모두 있는 날
- **강점 행동 '실천했다' 표시**: 마무리 기록의 "강점 행동: 실천했다"(자기 보고)
- **출석**: 출석 기록 원본에서 출석·지각인 날 / 기록된 수업일. 리추얼 기록으로 추정하지 않습니다.
- **과제 제출**: 제출 현황 원본에서 제출·지연제출인 과제 / 목록의 과제. 리추얼 기록으로 추정하지 않습니다.
- 기록이 없는 날을 실패로 해석하지 않습니다.

## 후보 문단 규칙

- 근거는 본인이 쓴 항목만 씁니다: 강점이 드러난 일화, 그 결과·알게 된 점, 오늘의 첫 행동, 강점을 위해 노력하고 생각한 것, 내가 나눈 감사. 동료가 쓴 문장은 쓰지 않습니다.
- 진료·증상, 제3자의 사정, 이름 가림 흔적이 있는 문장은 제외합니다(`EXCLUDE_PATTERNS`).
- 능력별 키워드 일치 수가 많은 순, 같으면 날짜순으로 최대 8개. 후보 id는 날짜와 원문으로 만들어 기록이 늘어도 바뀌지 않습니다.
- 초안 문장은 원문을 인용한 틀일 뿐이며, 공개 문장은 반드시 본인이 다듬어 승인합니다.

## AI 서비스 키

이 장치는 AI 서비스를 부르지 않으므로 키가 필요 없습니다. 나중에 AI 초안 기능을 붙이더라도 결과 파일에는 넣지 않고, 키는 환경 변수(예: `ANTHROPIC_API_KEY`)로만 읽어야 합니다.
